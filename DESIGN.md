# Design System: EasyConsole

## Overview

**Creative North Star: "The Calm Operator Workstation"**

A dense, desktop-first control panel for people launching and watching remote compute at a desk, in daylight or late at night. Tables, toolbars, side navigation, drawers, and inline states carry the work; nothing is decorative. Depth is quiet: surfaces separate by small tonal steps and soft shadows rather than by drawing the same hairline around everything, and color is spent only on state and problems.

There is one motion idea. A single raised **thumb** glides between choices: the active sidebar item, every segmented control, the task-detail tab underline, the settings section nav, and the mobile bottom-bar pill. Selection is never repainted per option; it travels. Everything else is short state feedback, and a route change is one 160ms fade: panels, titles, list items and figures inside a page do not add entrances of their own. The system refuses the boxy all-borders-equal look and alarm-colored action columns.

Two themes share one token set. Light is a warm off-white ground with a warmer sidebar neutral, white raised thumbs, and a blue accent. Dark is a cool graphite workstation with a light-blue accent and dark navy text on accent fills. The preference is `light`, `dark`, or `system` (default), stored under `easy-console-theme`; `system` removes `data-theme` from `<html>` and lets `prefers-color-scheme` decide, an explicit choice sets `data-theme="light|dark"`. The theme is applied before first render, mirrored to `<meta name="theme-color">` (`#fefdfa` / `#161a1f`), and pushed to the native titlebar through `runtime.setNativeTheme`.

**Key Characteristics:**
- Operational density: 36px controls, 56px shell header, table-first pages, no hero or stat-card rows.
- Tonal layering plus soft shadows; borders two-tier (soft decorative, strong interactive).
- One accent (blue), semantic color only for task state, validation, and failures.
- One gliding raised thumb as the shared selection gesture.
- Chinese-first, bilingual UI; light and dark themes from the same variables.

## Colors

Restrained neutrals (warm hue 95 in light, cool hue 260 in dark) with one blue accent; semantic hues appear only where something has a state.

The palette is defined once in `src/styles.css` under `@theme static` (light values) and overridden for dark in two identical blocks: `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` and `:root[data-theme="dark"]`. Every Tailwind utility, opacity modifier, and inline `var(--color-app-*)` follows the active theme. Do not duplicate the palette in `tailwind.config.ts`. Frontmatter keys map to `--color-app-*` (e.g. `border-strong` is `--color-app-borderStrong`); `*-dark` keys are the dark overrides of the same variable.

### Primary
- **Operator Blue** (accent): primary buttons, focus outlines and halos, active nav icon, caret and checkbox accent, progress fills, the task-detail tab underline. In dark it lifts to a light blue and its on-accent text flips to dark navy (`on-accent-dark`).
- **Blue Wash** (accent-soft): avatar disc, mobile bottom-bar pill, mobile "more" sheet active item, the palette's active option.

### Neutral
- **Warm Paper / Graphite** (bg): app ground and login background.
- **Sidebar Neutral** (sidebar): the left navigation column, one step warmer/darker than the ground so the shell reads as two planes without a heavy rule.
- **Surface** (surface): header, panels, tables, inputs, secondary buttons, mobile bottom bar.
- **Elevated** (elevated): dialogs, drawers, popovers, menus, action sheets, queue panels, routine toasts.
- **Panel** (panel): segmented-control tracks, settings section nav, hover fills for ghost controls and rows, disabled fields.
- **Thumb** (thumb): the raised selection thumb; white in light, a lifted graphite in dark.
- **Soft Border** (border) and **Strong Border** (border-strong): see the Two-Tier Border Rule.
- **Ink** (text) and **Muted Ink** (muted): primary text and secondary labels, placeholders, inactive nav.

### Semantic
- **Success / Warning / Danger / Info**, each with `*-soft` fill and `*-ring` outline, for status pills, validation, toasts, and API failures. Warning text uses `warning-text` for contrast on its soft fill.
- **Neutral soft / ring**: idle states, skeleton blocks, progress tracks (the shared `ProgressBar`: neutral-soft track, accent fill that slides in by transform, `role="progressbar"` with a label).
- **Row fills** (`rowHover`, `rowDanger`, `rowDangerHover`): opaque `color-mix` tokens (panel or danger-soft over surface) for table rows, so a sticky action cell repeats its row's fill exactly without its own arbitrary mix. Only failed and abnormal rows carry `rowDanger` at rest; running rows stay plain.
- **Code and Terminal** (`code-*`, `terminal-*`): intentional dark inspection surfaces in both themes; never substitute generic slate/sky palette classes. The in-app SSH terminal also offers user-selectable xterm presets (light, "hacker", and a custom 16-color palette whose default is Catppuccin-like, in `SshTerminalTab.tsx` and `app-settings.ts`); those are terminal content colors chosen by the user, not app chrome, and stay outside the token set.

### Named Rules
**The Two-Tier Border Rule.** `border` is the soft decorative boundary for panels, dividers, and table rules. `border-strong` is required wherever the boundary is the only cue identifying an interactive control (inputs, selects, textareas, secondary buttons, the header search field), because `surface` and `bg` are near-identical and the soft border sits well below the 3:1 WCAG 1.4.11 non-text minimum there. The strong border measures 3.52:1 on surface, 3.39:1 on bg, 3.13:1 on panel, 3.32:1 on sidebar in light, and 3.77:1 on surface, 3.32:1 on panel in dark.

**The Color Means Trouble Rule.** Color is reserved for state and problems. Routine confirmations sit on neutral surfaces with a colored icon; only errors get a tinted fill. Row actions are neutral at rest and take warning/danger color only on hover or focus. Running is the normal state of this product: it keeps its blue pill but never a row fill or a looping animation; failed and abnormal rows are the only rows with a fill. Settings (release condition, default image, counts) are neutral tags told apart by icon, never by hue.

**The One Variable Set Rule.** Both themes use the same `--color-app-*` and `--app-shadow-*` names. Never branch on theme in component code; if a value differs per theme, it is a token.

## Typography

**Body Font:** Inter Variable (with Inter, system UI, PingFang SC, Microsoft YaHei UI fallbacks)
**Mono Font:** JetBrains Mono Variable (with SFMono-Regular, Consolas)

**Character:** One neutral grotesque at fixed rem sizes and compact line-heights, tightened slightly with negative tracking on titles; Inter's `cv11` and `ss03` features are on globally. Both faces are self-hosted through `@fontsource-variable`.

### Hierarchy
- **Brand** (600, 1.25rem, -0.02em): the EasyConsole wordmark on the login column only.
- **Headline** (600, 1.0625rem, 24px line, -0.015em): the shell header page title; task-detail name steps to 1.125rem.
- **Title** (600, 0.9375rem, -0.01em): dialog and drawer titles; dashboard summary figures.
- **Body** (400, 0.875rem): default UI text, table cells, nav items, buttons (500).
- **Label** (500, 0.75rem, 20px line): badges, segmented options, field help, toast descriptions.
- **Group Label** (500, 0.6875rem, muted, sentence case): sidebar group headings (工作负载 / 资源 / 系统), the `Ctrl K` key hint, mobile bottom-bar captions.
- **Mono** (0.75rem): paths, hosts, IDs, logs, terminal.

### Named Rules
**The Targeted Tabular Rule.** Tabular numerals apply only to `time` elements and `.app-numeric` (figures that change in place or are compared). Never table-wide: Inter's tabular forms also widen hyphens and colons and spread out task names.

**The Base Layer Rule.** Element defaults (`font: inherit` on controls, focus styles, placeholder color, scrollbars) live in `@layer base` so utilities can size controls. Never add unlayered element resets; an unlayered font reset once pinned every control to 16px. On coarse pointers, text fields are forced to at least 16px so mobile browsers do not zoom on focus.

## Layout

The desktop shell is the primary target: a resizable left sidebar (8px drag handle, 24px on touch) on the sidebar neutral, and a flexible content column under a 56px header. The sidebar groups routes into Workloads, Resources, and System, and ends with an account row (initial disc, name, group, ghost logout) above the theme and language switches. The header holds the page title, a 224px search field ("搜索或跳转…" with a `Ctrl K` hint, collapsing to an icon button below `sm`), and a ghost status button (downloads, image commits, app updates) with a count badge. The task-detail route titles itself "实例详情". The header gains a bottom rule and soft shadow only after content scrolls more than 4px beneath it.

Pages use full-width work surfaces, compact toolbars, and table-first layouts. Main content padding is 24px at `md`, 20px at `sm`, 12px on phones. The dashboard opens with a status sentence (running, queued, range runtime, cost) separated by soft vertical rules from `sm` up and laid out as a two-column grid on phones (no rule can strand at a wrap), not a stat-card row; beside it sit the auto-refresh choice (default 1 minute, remembered) and an "更新于…" freshness line. Pages lead with their list; long creation forms open on demand (Scheduled Tasks opens its form from "新建计划", the empty state, or an edit). Avoid nested cards and avoid wrapping every section in floating panels.

Below 768px the shell switches to a bottom navigation bar with a sliding accent pill and a "more" action sheet carrying secondary routes, theme, language, and account. Dialogs become bottom sheets or full screen, tables square their corners and scroll horizontally, and batch/draft bars float above the bottom bar. Dense tables degrade through wrapping, horizontal scrolling, or compact controls rather than hiding required actions. Touch targets are at least 44px on coarse pointers (24px for checkboxes and radios). The login page is a centered 360px branded column: logo, wordmark, tagline, then a single form panel.

## Elevation & Depth

A hybrid: tonal layering does most of the work (sidebar, bg, surface, panel, elevated), and a small named shadow vocabulary adds lift where something is raised or floating. All shadows are CSS variables (`--app-shadow-*`) exposed to Tailwind as `shadow-raised`, `shadow-shell`, `shadow-popover`, `shadow-modal`, `shadow-stickyColumn`, `shadow-stickyColumnSubtle`; dark redefines each with black ink plus a faint white hairline. Overlays use `--app-overlay` (light: graphite at 36%; dark: near-black at 62%).

### Shadow Vocabulary
- **Raised** (`shadow-raised`): selection thumbs, primary/secondary/danger buttons.
- **Shell** (`shadow-shell`): panels and the task-detail summary strip; barely there.
- **Popover** (`shadow-popover`): menus, popovers, toasts, action sheets, login panel, mobile floating bars.
- **Modal** (`shadow-modal`): dialogs, drawers, terminal modal.
- **Sticky column** (`shadow-stickyColumn`, `shadow-stickyColumnSubtle`): the sticky table action column's left edge. Never arbitrary shadow values.

### Named Rules
**The Elevated Surface Rule.** Anything that floats (dialog, drawer, popover, menu, action sheet, toast) sits on `elevated` with a popover or modal shadow, never on plain `surface`.

**The Earned Depth Rule.** The shell header is flat at rest and only gains depth when content scrolls under it.

## Shapes

Gently rounded and tiered by role. Controls (buttons, inputs, nav items, segmented tracks) are 8px; panels, dialogs, drawers, popovers, menus, and toasts are 12px; bottom sheets round only their top corners. Inside an 8px segmented track (2px inset) options and the thumb use 6px so the curves stay concentric. Status uses a fully rounded pill; release conditions use a squared 5px tag. The avatar disc, status dot, count badge, and mobile nav pill are circles or full pills.

## Components

### Buttons
Quiet and solid; color only on the primary and destructive fills.
- **Shape:** 8px radius, 36px tall (32px compact icon buttons, 44px on coarse pointers), 12px horizontal padding, 14px medium text, 8px icon gap.
- **Primary:** accent fill, on-accent text, raised shadow; hover darkens with `brightness(0.94)`, active `0.9`.
- **Secondary:** surface fill, strong border, raised shadow; hover moves to panel fill and muted border.
- **Ghost:** muted text, no fill; hover panel fill and ink text. Used for icon actions, logout, header status.
- **Danger:** danger fill, on-accent text, raised shadow; reserved for confirmed destructive actions.
- **Press:** every interactive control scales to 0.97 for 60ms on press; disabled at 50% opacity without shadow.

### Status Pill and Release Tag
Two shapes so state and setting never read alike.
- **Status pill:** full-round, label type, soft fill + matching inset 1px ring + leading 6px still dot. Running = info, completed = success, failed/abnormal = danger, queued/paused/exhausted = warning, otherwise neutral. No pill animates; always text plus color.
- **Release tag:** 5px squared, neutral-soft fill, ink text, no ring, no dot, a muted 12px icon: manual = `Hand`, timed = `CalendarClock`, after-end = `Flag`. The same neutral tag carries the images page "默认" mark (`BadgeCheck`).

### Cards / Containers
- **Panel:** 12px radius, surface fill, soft border, shell shadow; no entrance of its own (the route fade covers it).
- **Internal padding:** 12px to 24px; settings rows 16px x 12px with dividers between rows instead of nested cards.

### Inputs / Fields
- **Style:** 36px, 8px radius, strong border, surface fill, 14px text, muted placeholder; hover border goes to muted.
- **Focus:** text fields swap the outline for an accent border plus a 3px accent halo (24% light, 32% dark). Buttons, links, checkboxes, and separators get a 2px accent outline at 2px offset; table regions, list rows, and tabs inside scrolling strips draw it inset (`-outline-offset-2`) so the scroll edge cannot clip it. The color is `--app-focus-color`: the app accent, except on the dark terminal chrome (`.app-terminal-chrome`), where it is `terminal-accent`, because the light-theme accent falls under 3:1 there; light cards inside the terminal take the app accent back. Components never replace the outline with a `ring`.
- **Disabled:** panel fill, muted text, not-allowed cursor.

### Navigation
- **Sidebar:** 36px items, 14px text, 16px icons, muted at rest with panel hover; the active item is ink, medium weight, accent icon, and sits on the gliding white thumb. Group labels are sentence-case group-label type, not kickers. The 任务实例 item carries a danger count of instances that failed since the user last looked (cleared by opening the list, or per task by opening its detail page); the mobile bottom bar shows the same count on its icon, and failure toasts carry a "查看日志" action to that task's log.
- **Task-detail tabs:** an accent bar glides under the active tab along a soft bottom rule.
- **Settings section nav:** sticky panel-filled strip whose raised thumb follows scroll-spy. Section headers are plain headings with an inline muted icon, not boxed icon tiles.
- **Mobile bottom bar:** surface bar with 11px captions; an accent-soft pill glides behind the active icon.

### Toasts and States
- **Toast:** 12px, popover shadow, bottom-right, max four. Success and info sit on elevated with a soft border and a colored icon; errors use danger-soft fill and danger ring and persist 8s (others 3.5s). Hover or focus pauses the timer.
- **Empty / Error:** centered 44px icon disc (panel + ring, or danger-soft + danger ring) above a short message and actionable description.
- **Loading:** skeletons take the shape of the content they stand in for (the dashboard shows its status line, three attention columns, and chart panel as neutral-soft blocks) and carry the `role="status"` label; a centered spinner is only for small inline regions.
- **Mobile sheet:** the bottom "more" sheet sits over an `--app-overlay` scrim that stops at the bottom bar, so the bar stays live and tapping the scrim closes the sheet.
- **Shortcut labels:** show `⌘` on Apple platforms and `Ctrl` elsewhere (`runtime.isApplePlatform`).

### Sliding Thumb (signature)
One absolutely positioned indicator per group, placed by `useSlidingIndicator` against the selected element (`aria-current="page"`, `aria-pressed="true"`). It moves with transform, width, and height over 280ms on the ease-out curve and fades in only once measured. Width and height only change between options of unequal size; the indicator is absolute and `pointer-events: none`, so its own layout is the only layout that runs (detectors flag the `width` transition; it is intended). Used by `SegmentedControl` (theme, language, ranges, metric toggles), the sidebar, task-detail tabs, settings nav, and the mobile bottom bar. New mutually exclusive choices reuse it instead of per-option selected backgrounds.

### Motion
- **Tokens:** fast 120ms (color, border, shadow, opacity), standard 180ms (transform, header shadow), emphasized 280ms (thumb travel, drawer enter); ease-out `cubic-bezier(0.16, 1, 0.3, 1)`.
- **Routes:** one entrance per navigation: the routed page fades in over 160ms with 4px of rise (`.app-page-enter`). No view transition, no title fade, no panel entrance (`Panel` has none), no staggered items, no counting figures.
- **Entrances that remain:** overlay 180ms fade; dialog 240ms fade + 10px rise + 0.97 scale; drawer 280ms slide from 28px; bottom sheet rises 24px; toast 260ms; the login panel once.
- **Exits:** dialogs, drawers, shell popovers, and the mobile "more" sheet animate out over 150ms (ease-in, faster than they enter). `lib/exit-motion.ts` re-inserts the node React already removed as an inert, `aria-hidden` ghost and plays Web Animations keyframes on it, so tests and assistive technology see the surface gone at once. Toasts slide 24px right and fade over 170ms before leaving the stack.
- **Theme:** switching light/dark crossfades the window once over 160ms (`::view-transition-old/new(root)`); without view transitions or with reduced motion the swap is instant.
- **Within a page:** task-detail tab panels slide 10px toward the direction of travel (none on first render); settings groups and `<details>` bodies unfold with a 220ms fade and 6px drop; menus pop from their trigger (`app-pop-enter` plus an `origin-*` class); status pills ease between state colors over 300ms.
- **Live:** the dashboard sentence's running count is the one looping element (a 2.2s ring on its dot). Status pills in tables and lists hold still dots. Live data is shown as text instead: the log toolbar reads "实时跟随 · 更新于 N 秒前" while it re-reads a running task's log every 6s.
- **Reduced motion:** entrances, tab slides, unfolds, and menu pops keep a 120ms fade and drop travel; the thumb fades instead of travelling; toasts only fade; surface exits and the theme crossfade are skipped; press scale, the live ring, spin, and pulse stop.

### Desktop behavior
Dialogs and popovers are keyboard-accessible, trap focus, close on Escape, and restore focus when closed. They stack: every dialog, drawer, sheet, menu and floating panel registers with `lib/overlay-stack.ts`, only the topmost one answers Escape and traps Tab (a picker over a form closes alone), Escape during IME composition is left to the input method, and page shortcuts (`g` jumps, `?`, `Ctrl K`, j/k) stand down while a modal is open. destructive or long-running actions stay behind explicit confirmation, and the confirm states the consequence (release shows runtime, cost so far, and that container-local data is destroyed). Unsaved-change prompts use the in-app confirm dialog, never `window.confirm`. In the task table the row action slot only ever means release; deleting an ended task's record is the last, danger-toned item in More. The keyboard row cursor is a 2px accent frame (`.app-row-active`, `.app-card-active`); j/k from anywhere on the page enter the list, moves are announced through a polite live region, and only the current row's controls are Tab stops. Desktop-only actions (in-app SSH, system terminal, VS Code) are first-class desktop controls and appear in the browser build only when the runtime supports them.

## Do's and Don'ts

### Do:
- **Do** take every color from `--color-app-*` so both themes follow automatically; add a token when a value must differ per theme.
- **Do** use `border-strong` on any control whose edge is its only affordance; keep `border` for decoration.
- **Do** put floating UI on `elevated` with `shadow-popover` or `shadow-modal`.
- **Do** reuse the sliding thumb (`SegmentedControl` or `useSlidingIndicator`) for mutually exclusive choices.
- **Do** keep state motion at or under 280ms on the shared ease-out curve, and give every animation a reduced-motion path.
- **Do** show task status as a rounded pill with dot and text, and release condition as a squared tag.
- **Do** use `.app-numeric` or `<time>` for figures that change in place or are compared down a column (durations, times, sizes, costs).
- **Do** let focus fall through to the base 2px accent outline; never replace it with a translucent ring.

### Don't:
- **Don't** draw equal-weight borders around every block or nest cards; separate with tonal steps.
- **Don't** color row actions at rest; warning/danger color appears on hover or focus only.
- **Don't** tint routine success or info toasts; tinted fills mean errors.
- **Don't** animate page loads beyond the 160ms route fade, or loop anything except the dashboard's running count.
- **Don't** apply `tabular-nums` to whole tables.
- **Don't** add unlayered element resets or arbitrary `shadow-[...]` values.
- **Don't** use uppercase tracked eyebrow labels; group labels stay sentence case.

## Language

Chinese is the primary interface language, with English available through the language switch. See `I18N_GUIDELINES.md` for the full copywriting philosophy, terminology table, and review checklist. Every user-facing string must go through one of these so the shell, dialogs, toasts, empty states, settings, native errors and run logs all stay bilingual:

- React components: `text(zh, en)` from `useI18n()`.
- Non-React modules under `src/lib/`: `i18nText(zh, en)`, or an explicit `locale` parameter when the caller already has one.
- Module-level tables: `{ zh, en }` pairs read with `localizedText(entry, locale)` from `src/lib/format.ts`.
- Rust (`src-tauri/src/lib.rs`): `trf!("中文", "English")`, which is `format!` with a language switch. Wrap every user-facing `format!` and `to_string()` literal.

`easy-console/no-bare-cjk` enforces this in ESLint. Where a string genuinely has to match localized text produced elsewhere — status messages coming back from Rust, for example — disable the rule on that line with a comment explaining why.

### Which mechanism

`text(zh, en)` is the default and the intended one for text that lives next to the UI. Keeping both languages on the same line is what stops them drifting apart.

The `t("key")` dictionary in `src/lib/i18n.tsx` is for strings selected **by data** rather than written inline: the navigation table, the shortcut table, and route titles pick their key at runtime and need a `TranslationKey` to stay type-safe. Do not add dictionary keys for one-off component text — that is how the dictionary accumulated 31 dead entries, all of which were pruned once the rule above made them visible.

The webview pushes the active locale to the native side through the `set_locale` command. The CLI and MCP resolve their own locale from `--lang`, then `EASY_CONSOLE_LANG`, then the system locale, then English.
